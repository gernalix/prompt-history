## Fixed-input benchmark

Inputs were frozen as online SQLite backups (Roadmap and Switcher), an 800-row
Codex index plus its 800 metrics files, and 6,680 exporter conversations (4.4 GB).
Only test copies were changed. Runs used separate transient systemd cgroups, with
`/proc/self/io`, `getrusage` and sampled `memory.stat` (20 ms). File reads reported
below are logical `rchar`, not physical device bytes or SQLite page-cache misses.
Warm filesystem cache was retained; no system cache eviction or memory limit.

| Workload (3 repetitions) | Before median | After median |
| --- | ---: | ---: |
| No changes, elapsed | 0.540 s | 0.175 s |
| No changes, process CPU | 0.533 s | 0.176 s |
| No changes, logical reads | 388.4 MB | 3.53 MB |
| No changes, records examined | 4,024 | 0 |
| No changes, process writes | 67,704 bytes | 0 |
| One late metric update, elapsed | 0.568 s | 0.186 s |
| One late metric update, CPU | 0.545 s | 0.179 s |
| One late metric update, logical reads | 388.5 MB | 3.80 MB |
| One late metric update, records examined | 4,024 | 2 |

Idle elapsed ranges: 0.531–0.669 s before, 0.170–0.175 s after. Metric-update
ranges: 0.558–0.626 s before, 0.180–0.188 s after. Python RSS: approximately
30 MiB before and 35 MiB after; checking exporter files individually costs some
Python memory/time but detects corrections missed by manifest-only checkpoints.
Changed SQLite sources are conservatively rescanned; unchanged SQLite sources
are not reopened. Metrics files still require 800 stats; exporter files require
6,680 stats. There is no claim that all source work becomes constant-time.

One-time checkpoint verification measured 14.6 s, 43 MiB RSS and about 2.8 GiB
cgroup memory, including roughly 2.8 GiB file cache and only 31 MiB anonymous
memory. Subsequent idle cgroups peaked around 24–25 MiB. This demonstrates how
large cgroup accounting can come from filesystem cache. The historical 1 GiB
service peak has no contemporaneous anon/file split; its exact cause remains
unproven. This change does not claim a measured reduction in Python RSS.
